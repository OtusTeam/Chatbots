## Занятие 7: структура кода

## Точка контроля

* `/start` → появляется меню.
* Кнопки меню: **FAQ / О нас / Связаться** работают.
* `/prof` → анкета проходит до конца (профессия → уровень → итог).
  **Что фиксируем как “улучшаем”:**
* После анкеты клавиатура должна скрываться.
* Нужен явный **Storage** (MemoryStorage).
* Единый стиль роутеров/хендлеров.
* Единые ошибки и нормальные логи.

---

## Доводим структуру проекта 

**Добавляем слои:**

* `app/states/` — состояния FSM
* `app/models/` — модель результата анкеты
* `app/services/` — тексты/справочники/сборка итогов
  **Правило:**
* Handler = “принял событие → вызвал сервис → ответил”.
* Тексты/списки/правила — не держим в handlers.

---

## Единый стандарт handlers и подключение роутеров

* Один файл = один сценарий (menu / questionnaire / common / echo).
* Имена функций уникальные и говорящие.
  **Практика:**
* Делаем “реестр роутеров” (один модуль, где собираем `include_router()`), чтобы `bot.py` не превращался в простыню.

---

## States: состояния FSM в отдельном модуле

* Все состояния анкеты в `app/states/...`.
* Имена состояний = шаги анкеты (например: `profession`, `level`).
  **Использование:**
* В хендлерах: `await state.set_state(ProfileStates.profession)` и т.п.

---

## Models: структура результата анкеты

* В `app/models/...` создаём структуру результата.
  **Зачем:**
* В конце анкеты собираем данные в один объект → проще вывод/лог/сохранение в БД позже.

---

## Завершаем сценарии корректно: скрываем клавиатуру 

**Скрытие клавиатуры (после финала анкеты / отмены):**

* Используем `ReplyKeyboardRemove()`.

---

## Storage: MemoryStorage

**Что делает storage:**

* Хранит текущий шаг FSM и данные анкеты между апдейтами.
  **MemoryStorage:**
* Быстро и удобно для разработки.
* Минус: перезапуск бота → состояние пропало.
  **Подключение (в точке входа):**
* `Dispatcher(storage=MemoryStorage())`
